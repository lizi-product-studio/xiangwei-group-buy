# 拼团微信订阅消息模板设计

关联任务：TASK-20260907-HOUSEKEEPING-REPLACE。

## 决定与使用边界

- confirmed：用户要求沿用原家政消费者小程序与微信支付，并由本项目设计拼团四类订阅模板及字段。
- 本文是模板选用与字段设计，不是微信后台已审核模板清单。实际模板名称、关键词编号、template_id 必须以该 AppID 的微信后台返回为准。
- 推荐模板优先提供用户决策所需的订单、点位、截止和退款信息；现有发送器缺少的变量明确列入配套适配，不虚构数据。完整信息通过消息跳转到对应订单详情查看。
- 四类模板对应现有七类事件，不增加营销通知。订阅授权与发送次数不能因复用家政 AppID 而假定已经具备。

## 四类模板与字段

下表名称是选用/申请时的业务语义，非已确认存在的微信模板库标题。短文本按不超过 20 字符、短状态按不超过 5 个汉字设计，最终以选中模板约束为准。关键词编号不可自行按表格行号生成，须照抄已选模板。

| 类别 | 在模板库寻找的语义 | 建议关键词 | 值来源与示例 | 覆盖事件 |
| --- | --- | --- | --- | --- |
| 1 订单安排 | 订单服务进度、订单安排变更 | 订单编号；通知事项；安排说明；温馨提示 | 实际订单号；领取地点已确认；自提点已确认或团期已顺延；请查看订单中的最新安排 | 地点确认/调整、团期顺延 |
| 2 配送进度 | 订单发货、配送状态 | 订单编号；配送状态；自提点；温馨提示 | 实际订单号；运输中；实际点位短名称；到货后请凭订单取货码领取 | 发车 |
| 3 提货安排 | 提货状态、领取服务提醒 | 订单编号；提货状态；自提点；领取截止；温馨提示 | 实际订单号；待提货/即将截止/已逾期；实际点位短名称；实际领取截止时间；查看订单领取安排或处理结果 | 到货、领取截止提醒、领取逾期 |
| 4 退款结果 | 售后处理结果、退款处理通知 | 订单编号；退款金额；退款状态；退款原因；温馨提示 | 实际订单号；该笔已成功退款金额；退款成功；缺货或履约异常；其余商品安排请查看订单 | 部分退款 |

订单编号使用字符串类型；金额使用金额类型；领取截止使用时间类型；说明/点位/提示使用短文本类型；状态使用短状态类型或模板允许的文本类型。金额只有在已核实退款成功时才发送，不把申请已受理写成退款成功。

## 七种事件的用户可见说明

| 事件 | 说明（来自现有通知 title） | 模板组 |
| --- | --- | --- |
| SITE_CONFIRMED，地点已确定 | 本团领取地点已确认 | 1 |
| SITE_CONFIRMED，地点待调整 | 领取地点正在调整 | 1 |
| CAMPAIGN_POSTPONED | 团期时间已顺延 | 1 |
| VEHICLE_DISPATCHED | 本团货物已发车 | 2 |
| ARRIVED | 货物已到，请领取 | 3 |
| PICKUP_DEADLINE | 领取期限即将截止 | 3 |
| PICKUP_EXPIRED | 订单领取期限已到 | 3 |
| PARTIAL_REFUND | 部分商品异常退款已处理 | 4 |

第三类不能直接命名为仅适用于“到货成功”的模板，因为同一组也发送截止和逾期语义。第一类同理必须能涵盖地点安排与团期时间变化。模板库若无此覆盖，应申请匹配关键词/模板或重新审核分组，而非挪用含义不符的模板。

## 与现有实现的衔接

推荐方案需要新增真实变量：orderNo、notificationSummary、notificationStatus、pickupDeadlineAt、refundAmount、refundReason，以及点位短名称和中国时区格式化。实际金额必须关联触发该通知的退款结果，不能取订单总额代替。模板 ID 获得后还需这一步映射与测试，不能只填四个 ID 就宣布模板对接完成。

以下是**只使用当前发送器已有能力的简版候选**，仅当平台库存在相符模板且决定采用简版时使用。它把详情留在订单页面，不替代上面的推荐字段方案。

## 简版配置映射候选

以下 JSON 的键只是示意，不可直接作为生产配置；必须替换为微信后台实际的关键词键。值可以沿用，现有发送器支持固定文字与 `{{title}}`。

```json
{
  "thing1": "社区团购",
  "thing2": "{{title}}",
  "thing3": "请查看订单中的最新安排"
}
```

- SITE_TEMPLATE_DATA 使用“请查看订单中的最新安排”。
- DISPATCH_TEMPLATE_DATA 使用“到货后请凭订单取货码领取”。
- ARRIVAL_TEMPLATE_DATA 使用“请查看订单领取安排或处理结果”。
- PARTIAL_REFUND_TEMPLATE_DATA 使用“退款金额及进度请查看订单”。
- 服务端配置四个真实模板 ID；小程序按同一四个 ID 映射七种事件，二端一致。
- 消息跳转使用现有 `pages/order-detail/index?id=...`，不另开无订单上下文页面。

## 当前字段缺口与验收

现有发送器仅提供 `title`、`content`、`siteName`、`address`、`arrivalStartAt`、`arrivalEndAt`。它直接替换字符串，没有逐字段类型/长度规范化。
`content` 包含长文案，不能未经验证塞入受限短文本字段；地址也可能过长或为空。
`arrivalEndAt` 属于到货安排，不能当作系统按到货后第三个自然日计算的领取截止；订单号和退款金额也不是当前模板变量。
未来如选定模板必需这些字段，应读取真实订单/退款结果，格式化中国时区时间、金额和短文本，并加边界验证后上线。不能以固定示例金额/日期替代真实数据。

## 微信后台实际需要取得的内容

每类提供：真实 template_id、模板标题、关键词名称/类型/编号、模板所属类目与审核状态。用户可在原消费者 AppID 下选用或申请；设计完成不等于平台已配置。

配置后的验证：四模板映射七事件；用户显式订阅；发送字段合法且不超长；点击到正确订单；拒绝订阅/发送失败进入现有处理路径；实际体验版与正式版跳转环境匹配。

当前发送器按 NODE_ENV=production 固定发送到 formal，小程序体验测试的消息落点需要在真实联调前明确核验，不得将正式旧家政小程序的跳转当作拼团体验版成功。
