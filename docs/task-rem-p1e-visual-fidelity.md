# TASK-REM-P1E 登录 / “我的”视觉还原任务包

状态：UI 设计中
优先级：P1
视觉权威：用户 2026-08-27 明确批准的“我的”游客态原型截图
唯一实现负责人：研发前端（UI 规格批准后进入）
独立审查：代码审核 / QA（只读）

## 1. 目标

让消费者小程序的独立登录页、“我的”游客态和“我的”已登录态形成同一套品牌视觉，并以批准原型为基准完成实机还原。修复范围仅限页面结构、样式、真实图标 / 品牌素材与必要展示文案，不改变已通过的认证、权限、订单、支付、配送和回跳行为。

## 2. 输入证据

- 批准原型：`.visual-audit-2026-08-27/profile-fidelity/01-prototype-profile.png`
- 当前独立登录实机：`.visual-audit-2026-08-27/profile-fidelity/02-actual-login.png`
- 当前“我的”已登录实机：`.visual-audit-2026-08-27/profile-fidelity/03-actual-profile.png`
- 视觉审查：`.visual-audit-2026-08-27/profile-fidelity/audit-report.md`
- 认证契约：`docs/task-rem-p1d-mini-auth.md`

## 3. 必须完成

### 3.1 UI / UX 设计交付

输出同一 iPhone 12/13 视口下的三个高保真状态：

1. 独立登录页：微信快捷登录为主操作；本地开发环境可出现次级“开发体验登录”；协议、错误、加载和取消返回可见且层级清楚。
2. “我的”游客态：遵循批准原型的登录卡、订单入口、固定自提点、常用服务、底部导航结构；游客仍能选择固定自提点。
3. “我的”已登录态：与游客态保持同一品牌语言，展示身份、订单摘要、固定自提点、常用服务和退出登录。

视觉权威只约束视觉与信息层级，不授权删除现有功能。常用服务必须保留当前已经实现的“订单消息、开通意向、客服、帮助、关于”，并补齐原型要求的“隐私与协议”；如六个入口无法在 390 × 844 常态视口完整露出，页面应正常纵向滚动，不得通过删除入口、缩小关键文字或缩小触控热区强行塞入一屏。

设计规格必须明确：颜色、字号、字重、行高、间距、圆角、阴影、分割线、按钮层级、图标来源、卡片状态、安全区和滚动边界。不得继续使用“乡、付、团、提、售、区”等单字作为正式图标；必须使用真实品牌 / 业务图标资产或项目采用的图标库。

### 3.2 前端实现

- 仅在批准 UI 后修改 `apps/miniprogram/src/pages/login/**`、`apps/miniprogram/src/pages/profile/**` 及必要的共享视觉资产 / token。
- 不重写认证状态机，不改变 `loginWechat` / `loginDemo`、协议拦截、auth intent、30 分钟 TTL、取消 suppression、session epoch、PageLoadCoordinator / PageActionCoordinator、401 / logout 清理或写操作不自动重放。
- `develop + local HTTP + demo` 才显示开发体验入口；`trial/release/wechat/HTTPS/未知环境` 必须继续 fail-closed。
- 不修改后台、API、订单、支付、配送、售后、点位或业务范围。

## 4. 明确不做

- 不新增消费者账号密码、手机号注册、会员、积分、优惠券。
- 不修改底部导航的信息架构和既有页面路由。
- 不删除、合并或隐藏当前“开通意向”和“关于”等既有服务入口；视觉原型未出现的现有功能仍以当前产品基线为准。
- 不用文字占位、Emoji、手绘 SVG 或临时 CSS 图形冒充正式图标 / 品牌资产。
- 不部署、不上传、不写真实微信 / 生产环境。

## 5. 验收标准

### AC-01 同状态视觉对比

Given 批准 UI 与微信开发者工具使用同一 iPhone 12/13 视口、同一登录状态和相同演示数据，
When 并排查看设计稿与实机截图，
Then 页面结构、主次操作、品牌色、卡片层级、图标、字号、间距、圆角和底部导航应一致；除微信原生导航、安全区和开发体验入口外不得出现未经批准的视觉改造。

### AC-02 游客态

Given 用户未登录，
When 打开“我的”，
Then 显示登录引导、订单入口、固定自提点、常用服务和底部导航；不得退化为只有登录按钮的空页。

### AC-03 独立登录

Given 游客从受保护入口进入登录页，
When 页面稳定，
Then 微信快捷登录是唯一正式主操作；开发体验登录只在本地 demo 出现且视觉上明确为次级；协议、错误和返回操作可读可恢复。

### AC-04 已登录态

Given 用户完成登录，
When 回到“我的”，
Then 身份、订单摘要、自提点和常用服务使用与游客态一致的视觉体系；无文字占位图标，无旧身份闪现。

### AC-05 可读与可操作

正文、辅助文字和点击区域在微信开发者工具中可读可操作；小字与浅灰文字不得成为关键信息的唯一表达，重要触控目标应接近 88rpx；不得横向溢出或遮挡底部安全区。

### AC-06 功能回归

现有小程序 typecheck / 单测、`pnpm check`、`pnpm test:e2e`、`git diff --check` 全部通过；认证与跨身份隔离定向用例不得回退。

## 6. 视觉证据要求

- UI 交付三个批准画面及规格文档。
- 前端交付三个对应实机截图。
- QA 必须逐状态并排比较，不得以功能测试或单张截图代替视觉一致性判断。
- QA 最终只返回 `PASS`、`PASS WITH ACCEPTED RISKS`、`FAIL` 或 `BLOCKED`。

## 7. 回滚

视觉修改应局限于页面结构、样式和资产；若视觉回归或功能门禁失败，可按文件级变更撤回 UI 层调整，不回滚已通过的认证安全修复。
