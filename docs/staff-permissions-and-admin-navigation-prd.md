# 人员、权限与运营后台导航 PRD

## 文档信息

- **版本：** 1.0（待研发与 QA 评审）
- **日期：** 2026-08-14
- **作者：** 产品经理 Agent
- **评审人：** 项目负责人、研发 Agent、项目评测 Agent
- **关联反思：** [人员创建、权限与导航闭环缺失](product-reflection-staff-account-gap.md)

## 1. 执行摘要

我们要为平台负责人、运营人员和自提点负责人建立一套完整且可审计的“创建人员 → 分配角色与点位 → 完成履约任务 → 停用并回收权限”体系，并将运营后台按商品、团期、订单、物流、自提点、售后、财务和系统管理重新组织。这样平台可以不依赖内部用户 ID 或共享账号，安全地把到货确认和提货核销部署到真实自提点。

## 2. 问题陈述

### 谁遇到问题

- 平台负责人：需要开设员工、配置权限并对离职/换点人员撤权。
- 运营人员：需要创建商品、开团、安排配送、处理订单与异常。
- 自提点负责人：需要在到货和提货现场完成有限的履约动作。

### 当前问题

现有页面仅提供“输入核销员用户 ID 后授权”。页面没有员工创建、员工目录、账号激活、角色选择或点位绑定的完整入口；同时商品、团期和配送任务混放在同一页面。

### 为什么痛苦

- 一个新点位无法完成从人员入职到核销的首个工作日。
- 内部 ID 对运营没有业务含义，极易填错。
- 共享账号会造成越权和审计失效。
- 自提点负责人若进入全局后台，可能看到不应接触的订单、成本或财务数据。

### 证据

- 现有“核销员授权”页面提示运营者输入“核销员用户 ID”，但没有创建人员功能。
- 现有“配送与领取”页面同时显示商品表、创建商品和创建团期入口，违反单一工作主题。

## 3. 目标用户与职责

| 角色 | 核心任务 | 不应拥有的能力 |
|---|---|---|
| 平台负责人（SUPER_ADMIN） | 创建/停用内部员工、角色与点位范围、全局运营审计 | 无 |
| 运营（OPERATOR） | 商品、团期、订单、物流、自提点资料、异常处置 | 采购成本、退款执行、其他商业敏感数据 |
| 客服（CUSTOMER_SERVICE） | 查询订单、受理售后、补充证据 | 商品/团期配置、成本、退款执行 |
| 财务（FINANCE） | 支付、退款、对账、导出 | 商品/物流配置、点位管理 |
| 自提点负责人（PICKUP_MANAGER） | 本点位到货确认、现场异常、提货码查询与核销 | 其他点位、商品编辑、团期、采购成本、退款、全局订单和财务 |

🔶 **假设：** 一期以“自提点负责人”统一承担到货确认与核销；不再单独设计一个只有核销权限、却没有人员来源的“核销员 ID”角色。

## 4. 战略目标与成功标准

### 业务目标

- 让平台负责人在不接触内部数据库 ID 的情况下，完成一个新自提点负责人的入职与授权。
- 让自提点负责人在自己的工作台完成当天到货与领取任务，不需要学习运营后台。
- 让后台左侧导航与真实工作对象一致，减少找功能和错误操作。

### 可验收指标

- 100% 的点位负责人创建、授权、换点、停用动作都由后台页面完成并留痕；不再要求业务人员传递用户 ID。
- 新建负责人并绑定点位的完整操作不超过 3 个页面步骤：创建员工 → 设置角色/点位 → 激活。
- 服务端权限测试覆盖跨点位读取、跨点位到货确认、跨点位核销、成本读取、退款执行五类拒绝场景。
- QA 通过“创建负责人 → 登录 → 到货 → 提货 → 停用 → 再次访问被拒绝”的端到端流程。

当前基线未知，以上为发布验收指标，不虚构已有完成率。

## 5. 方案概述

### 5.1 人员与权限闭环

平台负责人在“系统设置 → 员工与权限”创建内部员工账号，填写员工姓名、账号名、手机号、角色和状态；对于自提点负责人，再选择一个或多个负责点位。系统生成内部员工编号用于审计，但编号不需要由运营输入或记忆。

一期采用现有后台账号体系扩展员工账号。创建后系统提供一次性初始凭据或激活方式，员工首次登录必须设置自己的密码；初始凭据不可再次明文查看。🔶 **假设：** 首发不接入短信或企业微信邀请，先用受控的首次激活/密码重置流程；后续再评估微信绑定。

员工状态为“待激活、启用、已停用”。停用员工或移除其点位范围后，服务端必须立即拒绝其后续访问，既有会话也必须失效或重新校验权限。员工不做物理删除，保留历史操作记录。

### 5.2 后台导航

```text
日常运营
├─ 工作台
├─ 商品管理
├─ 团期管理
└─ 订单管理

履约管理
├─ 物流管理
└─ 自提点管理

客户与资金
├─ 售后与异常
└─ 财务管理

系统
└─ 系统设置
```

| 一级菜单 | 页面职责与主要操作 |
|---|---|
| 工作台 | 今日待发布、即将截单、待发车、待点位确认、待领取、待处理异常；卡片跳转对应列表。 |
| 商品管理 | 新增、编辑、启用/停用商品；维护图片、分类、规格、默认售价、默认可售量。供应商备注/采购成本置于受限“采购信息”区域。 |
| 团期管理 | 创建和发布团期；选择商品，设本团价格/数量、区域、自提点和时间；看销售汇总。只有发布的团期对消费者可见。 |
| 订单管理 | 查询订单、查看支付/履约/售后进度，导出按团期和点位的装袋/拣货清单。 |
| 物流管理 | 创建配送、录入货拉拉运单、司机、车牌与预计时间，确认发车，查看待点位确认、已到货和配送异常。 |
| 自提点管理 | “服务区域 / 自提点 / 负责人账号与权限”三个页签；维护地址、提货时间、联系人、启停和人员绑定。 |
| 售后与异常 | “配送异常 / 提货异常 / 用户售后”三个页签；运营决定补送、换货、退款或驳回。 |
| 财务管理 | 支付记录、退款记录、每日对账、导出；历史撮合结算只读兼容页，仅财务/超级管理员可见。 |
| 系统设置 | 员工与权限、操作记录、通知失败记录、历史兼容数据。 |

### 5.3 点位工作台

自提点负责人登录后不显示上述全局导航，仅显示：

- 我的待确认到货：查看自己点位的配送和逐商品应到数量；提交实到/短少/破损/错点与证据。
- 我的待领取订单：仅查看本点位、可领取/已领取订单的必要信息。
- 提货码核销：输入或扫码后显示该订单商品、数量和异常提示；可确认全提、部分提货或登记现场问题。
- 我的账户：查看自己的绑定点位和退出登录。

## 6. 业务规则

### 6.1 员工创建与授权

1. 只有 SUPER_ADMIN 可创建、编辑、停用内部员工；不得由普通运营通过任意用户 ID 授权。
2. 员工姓名、账号名、角色为必填；手机号用于联系且在列表中脱敏显示。不得将消费者账号混入员工目录。
3. 自提点负责人必须至少绑定一个处于启用状态的自提点；解除最后一个点位前须二次确认，并立刻失去点位操作权限。
4. 一名负责人可绑定多个点位；所有读取和写入均按绑定点位服务端过滤。
5. 角色模板是固定的，不能在一期提供任意“勾选接口权限”的自由配置，以防形成无法审计的组合权限。
6. 创建、角色变更、点位变更、重置凭据、停用和恢复均写入操作记录，记录操作者、时间、前后状态和原因（停用/敏感变更时必填）。

### 6.2 核销与点位履约

1. 不再出现“输入核销员 ID”页面。
2. 提货码核销仅允许绑定该订单自提点的启用负责人执行。
3. 同一提货码只能成功核销一次；重复请求返回已领取状态，不得重复扣减可领取数量。
4. 到货确认、部分提货和异常登记均以商品数量为单位，正常商品不因其他商品异常而阻断。
5. 点位负责人只能登记事实，不能执行退款；退款由运营决定、财务执行。

### 6.3 导航与展示

1. “物流管理”页不得出现商品列表、“新增商品”或“创建团期”按钮。
2. “商品管理”的唯一主要操作是“新增商品”；“团期管理”的唯一主要操作是“创建团期”。
3. “收货区域”“核销员授权”“操作记录”“历史撮合结算”不再作为散落的一级菜单，按第 5.2 节归位。
4. 运营可见菜单与服务端权限必须一致；前端隐藏菜单不能替代权限控制。
5. 运营可见的名称、状态和动作必须使用中文业务语言，不能直接显示内部 ID 或英文枚举。

## 7. 用户故事与验收条件

### Story 1：创建自提点负责人

作为平台负责人，我要在后台创建一名自提点负责人并绑定点位，以便其完成到货和核销工作。

- [ ] 在“系统设置 → 员工与权限”可以新增内部员工，不要求输入系统用户 ID。
- [ ] 创建表单至少包含姓名、账号名、手机号、角色和状态；选择“自提点负责人”后显示点位多选。
- [ ] 未绑定启用点位时不能启用自提点负责人账号。
- [ ] 创建成功后系统生成审计编号和一次性激活/初始化凭据；列表不重复展示明文初始密码。
- [ ] 员工目录与消费者目录隔离，列表仅显示必要的员工信息和脱敏手机号。

### Story 2：调整和回收点位权限

作为平台负责人，我要变更负责人负责的点位或停用其账号，以便人员变动后权限立即正确。

- [ ] 可新增、移除负责人绑定点位，并显示变更前后范围。
- [ ] 移除点位后，该员工无法读取或操作该点位的数据。
- [ ] 停用后，该员工的登录和已登录会话均不能继续进行受保护操作。
- [ ] 历史到货、核销和异常记录仍保留原操作人，不因停用丢失。
- [ ] 所有变更可在操作记录中检索。

### Story 3：自提点负责人完成现场履约

作为自提点负责人，我要只看到自己点位的到货和待领取任务，以便快速完成现场工作且不接触平台敏感信息。

- [ ] 登录后只显示点位工作台和我的账户，不显示全局运营菜单。
- [ ] 待确认到货列表只包含绑定点位的配送。
- [ ] 输入/扫码提货码后，仅当订单属于绑定点位且状态可领取时展示商品明细。
- [ ] 可选择全提、部分提货或登记问题；重复核销不得成功两次。
- [ ] 尝试访问其他点位、商品管理、团期管理、财务、退款接口均被服务端拒绝。

### Story 4：运营按任务使用后台

作为运营人员，我要在独立菜单中维护商品、创建团期和安排配送，以便不在错误页面寻找功能。

- [ ] 商品管理页可独立完成商品创建/编辑/启停，不出现配送操作。
- [ ] 团期管理页可独立创建和发布团期，不出现商品主数据编辑或发车操作。
- [ ] 物流管理页可完成待发车到待点位确认的操作，不出现商品表、商品创建或创建团期按钮。
- [ ] 自提点管理页可维护区域、点位和负责人绑定。
- [ ] 宽屏、768px、390px 下导航、表格/卡片、空态、加载态和错误态均可完成任务。

### Story 5：审计和高风险权限

作为平台负责人和 QA，我要能验证敏感操作有记录且无法越权，以便追溯争议并保护资金和用户数据。

- [ ] 创建/停用员工、角色/点位变更、到货确认、核销、异常登记、退款决定和退款执行都有审计记录。
- [ ] 普通运营和点位负责人都不能读取采购成本、供应商商业字段或全局财务数据。
- [ ] 财务执行退款前可见订单、商品、数量和退款金额依据；点位负责人不可执行退款。
- [ ] 并发到货确认、重复核销、重复退款、刷新重试都有幂等/条件更新回归测试。

## 8. 非目标

- 一期不做多租户/加盟商组织体系。
- 一期不做任意权限勾选、复杂审批流或企业 SSO。
- 一期不接入短信、企业微信或货拉拉 API；先使用受控的内部账号激活和人工运单记录。
- 一期不恢复“采购与中心仓”作为日常主导航；旧链路仅保留历史兼容。
- 一期不做供应商门户、完整 WMS、供应商自动结算或自提点佣金结算。

## 9. 依赖与风险

| 风险/依赖 | 影响 | 缓解措施 |
|---|---|---|
| 现有后台认证模型不支持安全地创建/停用内部员工 | 无法完成账号闭环 | 研发先评估现有账号、会话撤销和密码重置能力；若不足，先完成最小内部账号生命周期再接页面。 |
| 点位负责人使用共享账号 | 无法审计且离职风险高 | 上线门禁禁止共享账号；每人独立账号并可停用。 |
| 为了方便而仅前端隐藏菜单 | 存在越权访问 | 所有数据读取/写入按角色和点位范围在服务端验证，并添加 API 反向权限测试。 |
| 当前新社区履约链仍在开发中 | 页面/状态可能与本 PRD不一致 | 研发暂停导航相关实现，按本 PRD重新评估；QA 以本 PRD验收。 |
| 食品异常和提货期限政策尚未完全最终确认 | 现场人员无法一致处理 | 保持现有“事实登记—运营决定—财务退款”边界；在上线前固化提货期与售后期。 |

## 10. 待确认事项

| 问题 | 默认方案 | 负责人 | 截止 |
|---|---|---|---|
| 内部员工首次登录方式 | 一次性初始凭据，首次登录强制设置密码；后续可加入微信绑定 | 项目负责人 | 开发前确认 |
| 自提点负责人是否允许一人管理多个点位 | 允许，按点位范围隔离 | 项目负责人 | 已采用默认方案，可调整 |
| 提货时是否增加手机号尾号核验 | 首发仅使用登录态内提货码；出现纠纷后可增加尾号二次核验 | 项目负责人 | 上线前确认 |
| 提货期限与提货后售后期限 | 当前建议：到货后 3 个自然日、质量问题 24 小时 | 项目负责人 | 上线前确认 |

## PRD 自评

### 最强部分

角色生命周期、点位隔离和导航职责已基于当前真实页面断点与已确认业务流程定义，验收条件可由 QA 直接测试。

### 最弱部分

员工首次激活方式和实际运营的提货/售后时间尚未由项目负责人最终确认，已作为明确待确认项而非假装已定。

### 高风险假设与验证

| 假设 | 风险 | 验证方式 |
|---|---|---|
| 一名点位负责人同时负责到货和核销 | 点位繁忙时可能需要分岗 | 首个点位试运营后记录峰值核销量与现场等待时间。 |
| 受控初始凭据足以支撑首发员工登录 | 凭据分发不安全或操作成本高 | 在预发布用新建、激活、重置、停用全流程演练；失败则优先补微信/短信验证。 |
| 按订单预装袋可降低点位复杂度 | 发货端增加包装工作 | 首团记录装袋耗时、差错率和点位核销耗时。 |

### 推荐下一步

研发 Agent 按本 PRD先评估账号生命周期与会话撤销的最小实现，再改造导航和页面；项目评测 Agent 用第 7 节端到端场景独立验收。
