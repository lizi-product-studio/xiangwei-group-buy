# TASK-REM-P1-A 员工入场与权限验收契约

本文件只补充 P1-A 的可验证实现边界，不改变 `README.md`、PRD 或 P0 退款契约。

## 角色默认页与最小初始化

| 角色 | 登录后的默认页 | 首次请求 |
| --- | --- | --- |
| SUPER_ADMIN | 系统设置 | 员工目录、可授权自提点 |
| OPERATOR | 运营工作台 | 区域、自提点、团期、订单 |
| CUSTOMER_SERVICE | 售后与异常 | 售后/异常队列自身加载 |
| FINANCE | 财务管理 | 退款、账本自身加载 |
| PICKUP_MANAGER | 我的点位工作台 | 仅本人授权点位的配送 |
| USER | 无 | 管理后台拒绝 |

页面切换后才加载该页面所需数据。令牌中的角色不能访问菜单外页面；401 会清除本地会话并回到登录页，403 保留可恢复的页面错误反馈。

顶部“刷新”只重取当前页的事实：售后页重取品质案件、取消申请和履约异常；财务页重取退款与账本，并展示加载、失败和重试反馈。退出、401 失效和新账号登录会原子清空所有页面数据、选择、错误与加载状态，再按新角色设置默认页；每个异步读取绑定当前登录 epoch，旧身份迟到的响应不得写入新身份页面。

## 员工、凭据和授权状态机

员工当前状态为 `ACTIVE ↔ SUSPENDED`，以及仅由凭据流程使用的 `PASSWORD_SETUP_REQUIRED`。历史输入值 `PENDING_ACTIVATION` 仅由一次性迁移转换为 `PASSWORD_SETUP_REQUIRED`，不属于当前公共状态，运行时不得接受或展示。创建和重置生成的明文临时密码只在响应中返回一次；关闭管理端对话框后不得再次读取。员工使用临时密码普通登录后必须完成强制改密，成功后撤销旧会话。

角色、授权点位、状态和重置凭据是敏感动作：管理端二次确认并要求原因，服务端也强制校验。服务端先对规范化后的变更前/后角色、状态和点位集合比较；只有实际权限事实变化或重置凭据才递增 `authorizationVersion` 并撤销目标会话，单纯修改显示名、手机号或重复保存相同角色/点位不得撤权。一次敏感变更在同一事务内计算唯一的 `nextAuthorizationVersion`，同时写入员工、凭据（角色和版本）、角色投影、点位范围、会话删除和带原因的审计记录。

会话保存签发时的 `authorizationVersion`。每次 bearer 认证均比对当前用户状态、员工状态、凭据角色和版本；不一致立即删除会话并按未登录处理。员工管理写入在事务开始后再次核验操作者的当前超管身份与版本，从而拒绝“请求认证后被撤权”的旧 actor。点位业务继续在执行时查询当前点位授权，不能只相信页面隐藏。

生产 bearer 管理认证只接受受管员工：必须存在 `ACTIVE` 的 `InternalStaff`，且它的角色、授权版本与 `AdminCredential` 完全一致；缺少员工记录的 legacy 凭据一律不能登录、认证或执行敏感写入。升级时先用 `bootstrap-admin` 创建或轮密受管超管（首次提供显示名、手机号；既有账号轮密要求 `BOOTSTRAP_ADMIN_ROTATE_CONFIRM=ROTATE`），再启用应用；脚本会在同一事务提升授权版本、撤销会话并记录审计。该顺序使升级无需依赖人工先修复在线账号，legacy 旁路也不会在生产继续存在。仅 `AUTH_PROVIDER=demo` 的隔离测试/演示 header 可不携带授权版本，绝不可作为生产 bearer 认证路径。

## 浏览器验收

浏览器回归需覆盖五个内部角色的默认页、菜单和初始化请求；USER 管理后台拒绝；SUPER_ADMIN 从 UI 创建员工，员工使用临时密码普通登录并完成强制改密；角色、点位、停用、恢复和重置后旧会话失效。375、768、1440 宽度均断言 `documentElement.scrollWidth <= innerWidth`，并能操作导航和页面主操作。任何未预期的 401/403、4xx/5xx、`pageerror` 或未处理 rejection 均为失败。
