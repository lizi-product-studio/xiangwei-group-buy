# ADR-20260831-01：服务覆盖与下单边界

## 决定

**CONFIRMED**：平台不再在应用启动时自动创建“全国”服务区域或默认自提点。消费者只能看到同时满足以下条件的服务区域：区域已启用并允许下单，且区域内至少存在一个地址、联系人和状态均有效的真实自提点。

未覆盖区域只能提交开通意向；不得进入支付、配送或自提承诺。

## 解决的冲突

历史 `docs/PRD.md` 和 `docs/go-live-checklist.md` 中“默认全国开放并预置默认自提点”的表述，与 2026-08-31 用户确认的 P0 修复方向相冲突。本 ADR 以当前用户决定为准，并由同次改动更新相关文档。

## 范围与非目标

- 本次移除伪履约初始化与消费者可见性，不写入演示城市、点位或订单。
- 本次不引入预约、点位容量限流、多仓或全国配送网络。
- 已存在的真实区域和点位继续由运营后台创建与维护。

## 验收

1. 新建内存或空 MySQL 存储启动应用后，不自动出现服务区域或自提点。
2. 没有启用自提点的区域不出现在消费者服务区域接口中。
3. 有启用真实点位、且区域允许下单的区域可见，并仅允许其有效团期进入公开目录。
4. 未覆盖地区仍可使用既有开通意向接口；该接口不产生交易或履约承诺。

## 回滚

若需恢复某一城市的履约能力，由运营在后台显式创建区域、真实点位和团期；不得恢复自动全国点位初始化。
