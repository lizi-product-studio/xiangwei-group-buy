# 每周支付与退款人工核对

用途：在自动账单对账尚未实现期间，财务每周完成一次只读核对；首次出现差异或订单量明显增加时，交工程评估自动化。本文是操作流程，不代表已经实际对账。

## 准备与完整性

1. 财务通过本人获授权的微信商户平台取得上一个完整自然周的交易和退款账单，记录账期、时区、下载时间及账单覆盖范围。不要在任务聊天中上传含个人信息的原始账单。
2. 后台订单查询可导出当前筛选结果，单次上限 10,000 笔，超出时按时间分段并检查交界重复/遗漏。订单创建时间与实际支付成功时间不同，不用创建时间过滤结果冒充同账期完整支付流水。
3. 后台退款记录和账务流水用于逐条复核。当前退款接口整单和部分退款各最多 500 条，不能以当前页面总额冒充全量账单；达到上限或无法证明完整时，技术人员按同一账期提供获授权的只读脱敏核对摘要，保持本周状态“未完成”。本流程不授权导出新的敏感数据。

## 匹配规则（以当前代码为准）

| 场景 | 匹配依据 | 核对内容 |
|---|---|---|
| 普通单支付 | 商户订单号对应订单 orderNo | 微信成功支付与本地支付状态、金额、支付凭证一致 |
| 多点位合并支付 | 商户订单号对应 checkoutBatch.outTradeNo | 先核对支付批次总额，再核对子订单分摊；不能用每个子订单金额重复计算整笔微信交易 |
| 整单或部分退款 | 商户退款号对应 providerRefundNo（后台“退款单”） | 逐笔核对成功金额、最终状态、所属支付/批次；多次部分退款分别核对 |
| 账务流水 | 关联单据 referenceId 与支付/退款事实 | 同一事件只记一次、借贷平衡；借贷平衡本身不能证明与微信一致 |

金额统一到分后核对。以支付/退款最终成功事实计算现金流；处理中、提交结果未知或失败单独列出，不提前计入成功。跨周退款按退款实际成功账期核对，同时保留原支付关联。商品销售额、支付现金流和商户结算到账额口径不同，不能直接以总额相等判断通过。

## 差异与关闭

记录：账期、检查人、来源文件摘要、来源行数、成功支付/退款笔数及金额、待定笔数、差异编号、关联单据、原因、责任人、复核时间。只在有完整来源、逐笔匹配且未解释差异为零时记为完成。

发现微信成功而本地未知/失败、重复金额、漏记或金额不一致时，保留原始证据，交工程只读调查并由财务跟进。不要为“对平”重复付款/退款、编辑账务数值或删除记录。真实补款/退款或修账需具体授权和独立验证。

当前能力依据：`apps/api/src/modules/payments/payment-service.ts` 的支付批次与退款关联，`apps/api/src/routes/finance-routes.ts` 的退款读取上限，`apps/admin-web/src/App.tsx` 的订单导出和财务记录界面。平台页面入口随平台变化，以获授权账号实际界面为准。
