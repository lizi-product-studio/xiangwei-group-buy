# 上线问题与解决方案

更新时间：2026-08-31。事实基线以当前 `codex/audit-remediation` 工作树、`docs/00-10` 契约和 `evidence/local-gates-2026-08-31.md` 为准。

## 当前结论

本地可修复的核心闭环已收口并通过自动化门禁；仍不能宣布生产可上线。剩余阻断来自真实 MySQL/Redis 容量证据、微信预发布、合规客服渠道、账号注销/留存规则、备份恢复演练和最终独立质量复核。这些不得用 memory/mock 测试代替。

## 已关闭的代码问题

| 问题 | 关闭证据 |
|---|---|
| 逾期未领取退款错误冲减销售收入 | 退款异常显式区分确认收入前/后；账本科目回归测试覆盖负债与收入两条路径 |
| 团期可无限顺延 | 团期记录顺延次数，最多一次；二次未达量自动取消退款 |
| 七类通知事件与四模板/小程序授权不一致 | 七类语义统一；四个唯一模板分组授权；顺延事件纳入站点/履约变更模板 |
| 人工通知仅填自由文本即可完成 | 必填批准渠道、外部会话/工单引用、联系结果和说明，并进入审计 |
| 区域意向隐私权利只有文案没有入口 | 用户可查看本人记录、更正 `NEW`、撤回未关闭记录；跨用户读取/操作拒绝 |
| 多商品售后 API 未被小程序使用 | 小程序支持多 SKU 选择、逐行数量/原因/说明及聚合校验 |
| 单实例周期任务重入与静默失锁 | 单实例防重入；Redis 租约逐步校验运行权；续租/失锁使 readiness 降级。真实 Redis 故障测试仍是发布门禁 |

## 仍为上线阻断

### P0：真实支付与微信预发布

- 真实 AppID/AppSecret 登录与隐私版本更新拒绝路径。
- JSAPI 小额支付、全额退款、逐行部分退款、重复回调、支付/取消竞争。
- 四套审核模板覆盖七类事件；分组授权、实际触达、失败后外部客服证据闭环。
- 备案 HTTPS、商户证书、公私钥、API v3 密钥与回调地址匹配。

责任：产品所有者 + 微信商户/小程序管理员。证据：脱敏体验版记录、商户单号/退款单号、回调日志与人工工单引用。

### P0：真实数据层、恢复与容量

- MySQL 8.4 空库迁移和幂等复跑；两个连接一致性、退款/通知租约和 Redis 调和租约测试。
- 生产备份、恢复到隔离库、RPO/RTO 记录。
- 以试点峰值至少 2 倍的订单/通知数据执行并发压测，记录 p95/p99、锁等待、失败率和聚合 payload 体积。
- 当前单行 JSON 聚合未满足无限扩区条件；无容量证据时只允许受控单区域试点，不能宣称可横向扩展。

责任：技术/运维。当前机器没有可用的 MySQL 8.4 + Redis 7.4 集成环境，因此保持 `BLOCKED_EXTERNAL_ENVIRONMENT`。

### P0：合规与责任人

- 批准客服可使用的合规外部渠道、告知方式、访问控制和留存期限；系统只记录引用，不采集未批准的联系方式。
- 产品、法务、财务批准账号注销与订单、支付、退款、争议、审计数据的删除/匿名化规则。在此之前不得对外承诺自助注销。
- 指定运营、财务、客服、点位和技术发布签收人及停发/回滚责任人。

## 发布前执行顺序

1. 在隔离环境启动 MySQL 8.4/Redis 7.4，执行迁移、强制集成测试、备份恢复和容量基线。
2. 在安全主机填入不入库的微信/支付/域名配置，启动预发布。
3. 由五类内部角色完成运营正反例；真实用户完成登录、支付、通知授权、分次领取、多商品售后和退款。
4. 补齐外部证据和风险责任人，完成独立 QA 与 Quality Governor 复核。
5. 只有所有 P0 关闭后才进入生产部署授权；不得强制推送、自动打标签或自动发布。

## 明确不做

- 不向生产写入演示城市、默认点位、订单或密钥。
- 不把 mock 成功当成微信/商户成功。
- 不在未知旧库执行清库或覆盖迁移。
- 不为“看起来完整”加入会员、优惠券、评价或多业务模型。
- 不在留存规则未批准时仓促实现不可逆账号删除。
