# 乡味集后台角色、文案与状态体验优化方案

更新时间：2026-09-14
适用范围：运营后台、点位工作台及与订单状态相关的小程序页面

## 1. 结论

当前原型的模块边界基本覆盖了社区团购主流程，但存在三类体验问题：

1. 页面在解释系统结构，而不是告诉当前角色要做什么。例如“覆盖全部自提点、不按当前自提点过滤”“不是独立档案”等内容不应成为首屏主文案。
2. 状态、任务和异常混在一起。状态被做成醒目的大框，容易被误认为按钮；同一业务在订单、履约、售后和退款页面使用了不同词汇。
3. 异常提示缺少对象关系。原型曾按“自提点相同”匹配异常，导致一个点位的一笔异常扩散到其他正常批次，出现“无异常但不可领取”的错误提示。

本轮原型先统一信息架构、状态词典、文案和异常呈现。确认后再映射到实际后台和小程序，不改动现有生产权限及订单数据。

## 2. 设计原则

- 页面标题回答“这里能做什么”，副文案只说明业务规则和下一步。
- 列表一行只保留一个主对象、一个状态、一个明确的下一步和必要操作。
- 状态使用紧凑标签；主按钮只用于当前可执行的主操作。
- 成功、进行中、待处理、已结束、异常使用稳定的语义颜色，不用品牌红表示普通进度。
- 页面级通知只放会影响整个页面操作的事项；行级异常放在对应对象附近，避免连续堆叠大面积黄色提示。
- 角色只看到自己能理解并能处理的数据。点位负责人不承担退款决策，财务不修改到货事实，客服不处理区域开通运营。

参考依据：Ant Design 的表格用于承载可筛选、排序和分页的结构化数据，Tag 用于标记状态；GOV.UK Design System 建议谨慎使用通知横幅，并将直接相关的信息放回页面主体。

## 3. 角色与导航调整

| 角色 | 默认首页 | 一级模块 | 页面重点 |
| --- | --- | --- | --- |
| 超级管理员 | 工作台 | 全部总部模块 + 系统 | 查看全局经营与待办；员工、权限和日志放在“系统” |
| 运营 | 工作台 | 商品、团期、订单、履约、区域与自提点、售后、运营治理 | 开团、发货、处理到货异常和运营决策 |
| 客服 | 售后 | 订单、取消管理、用户管理、售后、通知处理 | 查订单、受理售后、协助用户；移除区域开通意向 |
| 财务 | 退款待办 | 订单、退款待办、退款记录、账务流水 | 只处理已确认的退款义务和支付结果 |
| 点位负责人 | 到货确认 | 到货确认、领取核销、核销记录、本点团期 | 只看授权点位，确认实物和完成核销 |

导航命名调整：

- “发货管理”改为“发货与运输”，覆盖装袋、车辆、发车和运输中。
- “确认退款订单”改为“到货异常处理”，先说明业务事实，再说明退款是后续结果。
- 超级管理员登录后默认进入工作台，不再直接落到员工管理。

## 4. 全链路状态词典

### 4.1 订单状态

| 系统状态 | 用户可见文案 | 颜色 | 说明 |
| --- | --- | --- | --- |
| PENDING_PAYMENT | 待支付 | 黄色 | 等待用户完成支付 |
| PAID | 待履约 | 蓝色 | 已支付，等待成团或备货；支付时间单独展示 |
| READY_FOR_PICKUP | 待领取 | 蓝色 | 自提点已确认到货 |
| PARTIAL_PICKED | 部分领取 | 黄色 | 仍有商品未领取 |
| COMPLETED | 已完成 | 绿色 | 全部领取完成 |
| CANCELLING | 取消审核中 | 黄色 | 截单后取消等待审核 |
| CANCELLED | 已取消 | 灰色 | 流程正常终止，不视为系统错误 |
| REFUNDING | 退款处理中 | 蓝色 | 已提交支付渠道 |
| REFUNDED | 退款成功 | 绿色 | 退款完成 |
| REFUND_HOLD | 退款异常 | 红色 | 需要人工核对支付结果 |

“逾期未领”作为订单风险标记与订单状态并列显示，不再制造独立且重复的状态体系。

### 4.2 团期与履约状态

| 阶段 | 文案 | 下一步 |
| --- | --- | --- |
| DRAFT | 待开始 | 完成配置并开售 |
| OPEN | 报名中 | 等待截单 |
| LOCKED | 已成团 | 进入备货 |
| PACKING | 待发车 | 完成装袋、登记车辆并确认发车 |
| DISPATCHED | 运输中 | 等待自提点确认到货 |
| CONFIRMED | 已确认到货 | 正常商品开放领取，异常商品进入平台处理 |
| COMPLETED | 已完成 | 无需操作 |

### 4.3 售后与退款状态

| 阶段 | 文案 | 责任角色 |
| --- | --- | --- |
| PENDING_ACCEPT | 待客服受理 | 客服 |
| PENDING_OPERATOR | 待运营审核 | 运营 |
| PENDING_CONFIRM | 待运营确认 | 运营 |
| PENDING_EXECUTE | 待退款 | 财务 |
| EXECUTING | 退款处理中 | 财务 / 支付渠道 |
| SUCCEEDED | 退款成功 | 无需操作 |
| FAILED_HOLD | 退款异常 | 财务人工核对 |

## 5. 点位到货页改版

原来的三条黄色提示中，只有“日常蛋品 · 批次 B08”存在真实异常。另两个批次显示“无”，却因为同一自提点有一笔待处理异常而被错误关联。

新版结构：

1. “待确认到货”展示可操作的批次和商品明细。
2. “平台处理中”只展示真实关联的异常批次，内容为团期、批次、异常事实、受影响订单数和处理状态。
3. “近期到货记录”展示已完成批次；“无异常”改成“数量一致”，“无需处理”改成“已完成”。
4. 页面不再连续铺设黄色横幅。异常只限制对应商品，明确说明其他正常商品可继续核销。

数据关联规则：到货批次 → 本批次领取订单 → 对应异常订单。禁止再通过自提点名称推断批次关联。

## 6. 发货、订单与异常列表改版

### 发货与运输

- 列名改为“团期与车辆 / 履约状态 / 下一步 / 送达自提点 / 负责人 / 更新时间”。
- “待装袋”统一为“待发车”，“已发车”统一为“运输中”。
- 操作按钮使用“确认发车”，状态标签不再呈现为按钮。
- 下一步根据车辆是否已登记显示“登记车辆并确认发车”或“确认装袋并发车”。

### 订单列表

- “消费者”改为“用户”，“金额”改为“实付金额”，“状态”改为“订单状态”。
- 已支付但尚未完成履约的订单显示“待履约”，支付事实由“支付时间”表达。
- 正常取消使用灰色，只有退款失败、结果不明和系统阻断使用红色。

### 到货异常处理

- 列名改为“受影响订单 / 异常 / 商品 / 预计退款 / 处理状态 / 更新时间”。
- “可复算金额”改为用户可理解的“预计退款”。
- 主操作改为“确认并提交财务”，明确运营确认范围、财务执行退款的职责分工。

## 7. 文案规范

| 原文 | 新文案 | 原因 |
| --- | --- | --- |
| 覆盖全部自提点，不按当前自提点过滤 | 查看全部自提点订单 | 用用户目标表达 |
| 确认退款订单 | 到货异常处理 | 先说原因，再说处理结果 |
| 可复算金额 | 预计退款 | 避免系统术语 |
| 退款失败/挂起 | 退款异常 | 状态简短，细节放说明 |
| 运营还要确认退款订单，受影响数量暂不可领取 | 异常商品正在由平台处理，暂不可领取；其他正常商品可继续领取 | 说明影响范围和可继续动作 |
| 无 / 无需处理 | 数量一致 / 已完成 | 使用正向、明确的完成语义 |

文案句式统一为“当前事实 + 影响范围 + 下一步”，避免在用户界面解释数据库对象或技术实现。

## 8. 订阅提醒补充

小程序消息页不应让用户看到不断增长的“授权次数”。订阅动作改为“订阅本次提醒”，成功后显示“本次已完成”，当前订单不会再次要求授权；用户拒绝后仍可在站内订单消息查看进度。后续正式实现按实际订单的重要节点触发微信订阅请求，并保留拒绝和失败的恢复路径。

## 9. 验收清单

- 幸福路自提点只显示日常蛋品 B08 的真实异常，不再显示“无异常但不可领取”。
- 点位负责人不能看到其他自提点数据，也不承担运营或财务操作。
- 发货列表中的状态标签尺寸、颜色和按钮有明确区分。
- 订单、售后、退款详情与列表使用同一状态文案。
- 已取消、已驳回为灰色结束态；退款异常、处理失败为红色异常态。
- 页面级黄色提示最多一个，且必须影响页面整体操作；单行问题回到对应表格或卡片。
- 超级管理员默认进入工作台；客服导航不再出现区域开通意向。
- 小程序完成本次提醒订阅后不再继续显示授权按钮。

## 10. 落地顺序

1. 先确认本版可交互原型与状态词典。
2. 映射实际后台列表、详情、筛选项和权限可见性。
3. 修正真实 API 的异常关联查询，补充批次到订单的关联回归测试。
4. 更新小程序订单状态与订阅提醒交互。
5. 用运营、客服、财务、点位负责人四条任务路径分别验收，再进入服务器发布。
