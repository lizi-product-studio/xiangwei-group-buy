# 产品与体验重构说明

> 已更新：当前履约模式要求在团期开售前绑定已启用的固定自提点；用户下单前即可确认地点和地址。截团后只更新到货窗口、车辆与到货进度，不再临时确认或替换领取地点。最新页面与运营动作以 [履约与界面说明](interface-prototype-map.md) 为准。

## Interpreted goal

把当前“功能齐全但运营负担重”的拼团系统，重构成一个运营人员能快速开区、批量建点，消费者能快速看懂并下单的社区团购 MVP。

## Assumptions

- 平台首期仍采用“统一截单、集中发车、用户自提”的履约模式。
- 运营区域以城市级行政区为订单和履约边界，但运营人员不应逐个维护行政区底表。
- 首期运营范围聚焦河北省保定市，系统一次建立保定市区县/县级市服务范围；自提点随后按区县批量导入。
- 当前商品和团期接口还没有图片字段，本轮先使用项目内商品主图完成视觉重构，后续再把图片升级为商品数据字段。

## Complete product shape

### Core users

- 平台运营：开通区域、管理商户商品、创建团期、处理异常。
- 履约人员：创建发车批次、确认到货、处理自提。
- 消费者：确定自提点、浏览团购商品、下单、查看订单和取货码。

### Core business flow

1. 运营一键开通运营区域，系统自动建立城市服务范围。
2. 运营批量粘贴自提点资料，系统按城市自动归属。
3. 运营选择商品、服务区县与同区县自提点建立团期。
4. 系统按截单时间自动结团，生成履约任务或退款。
5. 消费者在小程序看到当前自提点可购买的团购商品并下单。
6. 到货后系统生成取货码，完成核销和后续结算。

## MVP scope

- 保定区县区域预设一键开通，接口幂等，重复执行不会重复建立区县。
- 自提点批量导入，支持“城市、点位名称、地址、日容量”四列。
- 后台工作台信息层级重做，突出待办和履约状态。
- 后台整体视觉重做，去除书法、印章、大口号和深色大色块。
- 小程序首页、团期详情、结算、订单、取货码统一改为商品优先的零售视觉。
- 使用本地商品图片替代文字占位图。

## Non-MVP scope

- 地图圈选服务范围、地址自动解析和经纬度纠偏。
- 全国完整行政区字典和自定义区域模板管理。
- Excel 文件上传、导入错误逐行修复工作台。
- 基于销量的选品、补货和线路智能推荐。
- 商品多图、视频、富文本详情和动态类目。

## Key pages and modules

- 后台工作台：待办、异常、关键数字、下一班履约。
- 服务网络：区域模板、城市覆盖、自提点、批量导入。
- 团期、商户商品、订单履约、财务、审计：保留能力，压缩装饰性文案。
- 小程序首页：自提点、活动提示、团购商品、订单入口。
- 小程序商品详情、确认订单、订单列表、取货码。

## Data model

继续复用 `service_areas` 和 `pickup_points`。区域模板是服务端常量，不新增数据库表；激活模板时批量写入保定服务区县。批量自提点仍写入既有表，避免引入迁移和双重真相。

## API design

- `GET /api/v1/admin/network-presets`：返回可用区域预设及已开通数量。
- `POST /api/v1/admin/network-presets/:presetId/activate`：幂等建立预设城市。
- `POST /api/v1/admin/pickup-points/batch`：按城市名称或行政区代码批量创建自提点。

## Technical choices

- 沿用 React + Ant Design、微信小程序原生、Fastify + Zod 和现有存储接口。
- 不新增框架和数据库表。
- 区域激活与批量导入均由服务端校验，前端只负责解析输入和展示结果。
- 视觉系统使用白色/浅灰底、珊瑚橙主色、绿色状态色；正文统一现代无衬线字体。

## Acceptance criteria

- 运营可以通过一次操作建立保定市 24 个区县/县级市，重复点击不会产生重复记录。
- 运营可以一次粘贴至少 10 个自提点并成功按城市归属。
- 首页首屏不再出现品牌口号，用户能直接看见自提点、价格、团期和购买入口。
- 后台导航、页面标题和关键操作在 1366px 及移动宽度下可用。
- lint、typecheck、test、build 通过；本地后台完成浏览器截图检查。

## Risks

- 当前区域预设属于代码配置，新增全国模板需要发版；后续可升级为可维护模板。
- 自提点地址没有地图校验，错误地址仍需运营复核。
- 当前演示商品图是项目本地素材，真实上线前需要商品图片上传与 CDN 方案。
- 支付、退款、权限和生产数据规则不在本轮改动范围内，继续沿用现有安全边界。
