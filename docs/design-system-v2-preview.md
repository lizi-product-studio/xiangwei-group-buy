# 乡味集设计规范 v2 · 预览稿

状态：2026-09-14 用户授权修订；待新版原型视觉确认。范围为运营后台、点位工作台和消费者小程序的原型及下一轮前端实现，不改变 API 权限、金额、库存、支付和履约规则。

## 1. 设计与实现边界

- 后台延续 Ant Design 的 Menu、Form、Table、Modal、Drawer 等组件能力，以暖白浅色导航统一品牌。原型中的原生 HTML 只用于演示，不作为替换成熟组件的理由。
- 小程序沿用微信原生 button、checkbox、switch、picker、input 和 textarea。网页原型使用对应 HTML 原生控件表达状态。
- 演示角色、网络结果、设备宽度和定位结果控制器必须放在设备框或正式页面内容外，并明确标注模拟；正式应用不带这些控制器。
- 品牌图只承担装饰或商品识别。商品图片仍来自后台上传；不能使用演示图片作为无图商品的假实拍。

## 2. 颜色、文字与尺寸

| Token | 预览目标值 | 用途 |
|---|---|---|
| ink | `#23312d` | 正文、标题 |
| muted | `#626c60` | 次要说明；不能用过浅文字承载必要信息 |
| page | `#faf8f2` | 页面底色 |
| paper | `#fffefa` | 卡片、导航与表单表面 |
| brand | `#c2412d` | 白字主按钮、品牌操作 |
| brand-soft | `#fff0eb` | 选中浅底 |
| success | `#3f6b35` | 成功文字及状态；同时有状态名称 |
| warning | `#85510b` | 警告文字；与浅黄色背景配合 |
| danger | `#b42318` | 错误、危险操作 |
| line | `#e6e3d8` | 装饰性分隔；交互控件边界需另验非文本对比 |
| focus | `#c2412d` | 2px 实线焦点，外偏 2px |

- 普通正文对比至少 4.5:1，大字号至少 3:1；不能只凭截图判断。装饰线无需冒充文字标准。
- Web 正文/表格 14px，辅助说明不低于 12px，页面标题 22–24px，区块标题 16–18px，正文行高 1.5–1.7。
- 小程序正文 14–16px 等效字号，辅助信息 13–14px，标题 20–24px。实现时换算 rpx 并验证系统大字体，不把固定模型尺寸当作真实设备适配。
- 间距采用 4/8/12/16/24/32px；相邻操作默认 12px，移动端不能依靠缩小按钮挤进单行。
- 后台控件默认 38–40px，紧凑表格可保留 32–36px 操作；移动关键触控命中区目标 44×44px，视觉图标可小于命中区。
- 卡片圆角 12–16px，输入框 8px，按钮 10–12px；仅标签和头像采用全圆角。

## 3. 页面框架与导航

| 宽度 | 后台布局 |
|---|---|
| ≥1280px | 232px 侧栏，内容弹性宽度，主体左右 24–32px |
| 1024–1279px | 可折叠侧栏；菜单文字不得裁切关键含义 |
| 768–1023px | 紧凑侧栏或抽屉；页面主操作与表格仍可见 |
| <768px | 顶部明确菜单按钮，侧栏抽屉和遮罩；选择页面后收起，焦点返回 |

- 一级表示业务模块，二级表示独立任务页；状态筛选用页面内标签，不复制左侧导航。
- 当前页面高亮；其父级在折叠时仍显示选中。二级菜单支持点击、Enter、Space、Esc 和焦点进入；不只依赖 hover，也不被滚动容器裁切。
- 面包屑表达模块/页面/详情层次；导航失败或无权访问返回该角色安全默认页。
- 点位负责人使用“点位工作台”，明确当前自提点；到货确认、领取核销、核销记录、本点团期均限当前授权点。

### 权限适配，不重定义授权

| 模块 | 页面 | 可见与操作边界 |
|---|---|---|
| 工作台 | 工作台 | 运营；超管保留现有入口 |
| 商品 | 商品列表、分类管理 | 运营/超管 |
| 团期 | 团期管理 | 运营/超管；状态决定能否修改 |
| 订单 | 订单查询、取消申请 | 运营/客服/财务按现有权限；财务订单查询保留，不能获得运营写操作 |
| 履约管理 | 发货管理、到货差异决定 | 运营/超管；财务不能决定退款范围 |
| 区域与自提点 | 服务区域、自提点 | 运营/超管；位置与员工授权分别校验 |
| 消费者 | 消费者查询 | 按当前消费者查询权限；不因原型给运营扩大隐私访问 |
| 售后 | 受理/决定 | 客服受理、运营决定、超管现有权限 |
| 运营治理 | 区域开通意向、通知人工处理 | 运营/客服按既有动作权限显示；通知人工处理只给客服/超管 |
| 财务 | 退款待办、退款记录、账务流水 | 财务/超管；不开放给运营 |
| 系统 | 员工、权限、操作日志 | 超管；保留其现有业务权限，紧急代办必须有原因和审计 |

修正上一轮评估建议：现有财务有订单查询入口，超级管理员有既有全局业务权限；本次不撤销这两项。新增“客服工作台”等建议不作为已实现业务功能承诺。原型权限树不构成后端可配置授权系统的实现证明。

## 4. 列表、表单、弹窗

- 列表结构统一为标题与主操作、筛选区、结果统计、数据区、分页。筛选条件提交后回显；区分无数据、无匹配结果和加载失败。
- 金额/数量列靠右且使用等宽数字；对象名称靠左；长文案可以换行或省略并提供完整详情。操作列不与普通文字混淆。
- 窄屏仅表格容器横滚，主页面不横滚；高频点位任务优先卡片。必要对象标识和操作必须可到达。
- 表单 label 关联控件，必填有文字或符号说明；错误贴近字段、说明修复办法；提交中防重复，失败保留输入。
- 对话框有可访问标题、初始焦点、焦点圈定、Esc 和关闭后焦点返回。危险操作默认聚焦安全项；未保存内容离开时提示。
- 保存、移除、取消、确认等按钮使用统一操作栏和 12px 间距，移动端允许纵向排列。
- 层级按页面/固定栏/弹出菜单/抽屉遮罩/对话框/提示分层；焦点所在元素不能被遮挡。采用组件库 portal 管理浮层，避免父容器 overflow 截断。
- 动画只解释变化，100–200ms；系统减少动态效果时停用骨架闪烁与非必要运动。

## 5. 小程序关键状态

| 流程 | 必须覆盖的原型状态 |
|---|---|
| 登录 | 未同意、授权中、拒绝手机号、接口失败、成功恢复来源、取消返回来源；按钮为“手机号快捷登录” |
| 游客 | 可浏览公开商品；私人订单/消息入口先登录；不显示假订单数量 |
| 商品/订单 | 加载、空、失败、重试；不同订单状态只显示当前允许操作 |
| 自提点 | 区域选择、点位选择、当前点回显、无覆盖；不得点到未开放区域后显示可下单 |
| 售后 | 多商品/数量/原因、提交中、失败保留、成功进度；部分领取的已领与待领数量一致 |
| 通知 | 站内消息与外部订阅分开；拒绝/继续授权/失败状态明确，不能承诺一定送达 |
| 客服/电话 | 有实际能力才调用；模拟演示明确标识；不可用时提供可返回的说明，不能死按钮 |

登录页不重新引入曾被微信审核指出的“微信快捷登录”品牌文案或官方图标。协议为可操作链接，返回后保留勾选状态。原型演示不会收集真实手机号或执行真实支付。

## 6. 自提点定位

沿用 [已批准定位规格](06-ux-spec.md#自提点定位规格p1-冻结基线)：新建先选区域，搜索地点，选择候选，确认图钉，核验行政路径，再保存。编辑时服务区域只读；未改变位置的普通编辑保留已存坐标且不触发重新核验。位置改变、重新启用时执行完整核验。

模拟器提供搜索失败、无结果、路径不匹配、重复点和验证通过，用来评审恢复路径。所有“通过”均标注演示，不能在搜索开始前宣称已定位。输入在失败后保留，路径不匹配禁止保存，疑似重复要求明确选择。

## 7. 验收与实施

原型验收包含 Web 768/1024/1280/1440，手机 320/375/390/430，长内容、键盘导航、主要失败/重试路径、颜色对比和浏览器控制台错误。截图只证明对应视口，微信原生大字模式、真实授权和实际设备仍在实现后验收。

原型通过后，将视觉/交互映射到现有组件，验证既有权限、登录状态和业务恢复逻辑，先提供用户预览再推进实际运行版本。生产数据、真实微信支付、订阅和地图服务不被静态演示修改。

参考：[Ant Design 导航](https://ant.design/docs/spec/navigation/)、[布局](https://ant.design/docs/spec/layout/)、[WCAG 2.2](https://www.w3.org/TR/WCAG22/)。44px 是本项目移动关键操作目标；WCAG 2.2 AA 的目标最小尺寸为 24px 且存在间距等例外，不能将 44px 错写成通用 AA 法定门槛。
