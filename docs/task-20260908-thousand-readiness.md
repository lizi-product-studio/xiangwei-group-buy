## 已证实的问题与风险

1. P1待办可达性：取消申请与品质售后在MemoryStore先取最近500，再由角色筛选，旧待处理申请可能被已处理/其他角色记录挤出；无分页入口。QA独立复现结果另附。
2. 容量架构：实际MysqlStore每个get/list方法仍使用全量SELECT FOR UPDATE并回写完整payload，全局串行；连接池20不等于20路并行业务。数据增长会影响浏览、认证、下单及后台任务。
3. 生产低负载快照为2核/约2GiB，API限制0.75CPU/384MiB；瞬时低CPU和内存不能推导峰值容量。
4. 本机没有docker/podman/colima/mysql/redis-server可用运行环境，真实数据层容量测试NOT_RUN；没有新压测结果，不提供虚构安全人数。
5. 每IP每分钟600请求的全局限流，会使共享网络用户共用配额；需在集中访问负载中验证，不应直接取消限流。
