# 产品调研记录

> 当前产品基准（2026-08-12）：团期开售前必须绑定服务区域内一个已启用的固定自提点；消费者下单前即可看到并确认地点、地址与预计到货窗口。截团后只能更新备货、车辆、到货窗口和到货状态，不能为已有订单确认或替换领取地点。本文保留调研假设，不覆盖 [履约与界面说明](interface-prototype-map.md) 与 `implementation_plan.md` 的现行规则。

> 状态：调研中。未确认的事项不得被当作产品规则实现。

## 已确认的商业模式

- 目标是可扩展至全国的社区团购平台；保定只是当前演示或首批区域，不是产品边界。
- 平台掌握货源：统一寻找并管理供货商，而非让商家或团长自行开团。
- 平台负责商品审核、商品上架、定价和创建团购活动。
- C 端用户选择自提点后浏览商品并下单；订单在截单后由系统自动按商品和自提点汇总。
- 供货商的货物先配送至平台仓库；平台统一收货、分拣，再配送至各自提点，用户到点取货。
- 首批重点货源为农产品和真空熟食。
- 一期以常温可存放的农产品、干货和真空熟食为主，不将需冷链的生鲜商品作为首批重点。
- 团购活动按农产品成熟、到货和可售批次不定期开启，不以每日或每周固定频率为前提；每一期必须向用户明确展示预计自提时间。
- 一期采用“一个团期 = 同一截单时间 + 同一预计自提时间”的规则；用户购物车不跨团期。
- C 端用户在提交订单时直接在线支付；采购、分拣和履约数量以已付款订单为准。
- 一期售后规则：截单前用户可自助取消并全额退款；截单后至到货前由运营审核申请；已取货订单如有缺货、破损或品质问题，用户可在规定时间内提交凭证申请售后。
- 自提点以合作门店、驿站或个人负责人的形式接入，而非平台自建门店。自提点负责人仅处理本点位的收货、保管、核销和现场问题，不负责推广、拉新或发团，也不可查看平台全量订单、采购或定价数据。
- 平台的主要获客渠道为短视频、既有客户和线下活动；品牌核心是宣传本县及周边的优质产品。县域支持可作为拓展助力，但不作为系统流程的必需条件。
- 一期仅向已具备库配和自提点交付能力的地区开放下单，不接入快递到家。未覆盖地区用户可选择省、市、区县并留下开通意向；这些需求用于后续开点和配送网络决策。
- 用户可在商品到达自提点的当天与次日取货；系统在到货时通知、取货期结束前提醒，逾期未取订单进入运营待处理，不自动扣款或报废。
- 自提点一期不按商品销售额抽佣，而是按实际完成核销的订单数支付固定服务费。服务费标准与结算周期后续确定。
- 供货商在开团前确认供货价、可供数量和预计送仓时间；截单后平台按已付款订单生成采购单，供货商送货至平台仓库。仓库验收数量、品质和批次后，合格部分进入供货商结算。
- 仓库至自提点的配送同时支持平台自配和第三方承运。每个配送批次记录配送方式、承运人/司机、预计到达和自提点到货确认；一期不依赖第三方物流 API 对接。
- 一期自提点由平台运营人工审核并开通，确保合作负责人、地址、营业时间和收货/保管能力可靠。自提点在线申请入驻放入后续扩张阶段。

## 一期角色边界

| 角色 | 一期主要职责 |
| --- | --- |
| 平台运营 | 供货商、商品、价格、团期、区域和订单异常管理 |
| 仓库人员 | 收货、质检、按自提点分拣、出库 |
| 自提点负责人 | 当前作为待点位映射的预留角色；到货确认由履约人员执行，已获授权的核销员负责核销和现场问题登记 |
| C 端用户 | 选择自提点、下单、取货、申请售后 |

- 一期只建设一个平台运营后台和一个消费者小程序。平台内部运营、仓库和履约人员在同一后台中按角色授权；不建设供货商后台、团长端或独立司机端。
- 合作自提点负责人使用同一小程序的受限“自提工作入口”执行本点位的取货码核销；到货确认待建立可审计的点位映射后再下放，不新建独立门店端或团长端。

## 尚待设定的运营参数

- 每期团购的具体截单时间与预计自提日期。
- 起步区域、仓库数量、仓库覆盖范围与开点计划。
- 自提点单笔核销服务费、结算周期与具体品质售后时限。
- 供货商的付款账期、缺货和验收争议的具体责任分担。

## 当前产品原则

- 先完成“平台统一采购、中心仓分拣、自提点交付”的标准闭环。
- 一期不把商家自助开团、团长自营店、好友凑人数成团作为前提。
- 上线、支付和部署事项仅在产品规则确认并验收后进入最后阶段。
