# 平台统一供货型社区团购：业务模式 V1（待确认）

## 一句话定义

一个由平台统一找货、采购、定价、开团和履约的社区团购平台。消费者在小程序选择已开放的自提点并预付下单；货物先进入平台仓库，再按自提点分拣配送，用户到合作自提点取货。

平台以宣传本县及周边优质农产品、干货和真空熟食为核心，通过短视频、既有客户和线下活动触达用户；系统架构支持全国扩展，但只向已具备仓配与自提能力的地区开放交易。

## 参与方与边界

| 参与方 | 负责什么 | 一期不负责什么 |
| --- | --- | --- |
| 平台运营 | 找供货商、维护商品、定价、开团、采购、区域管理、异常和售后 | 不把商品、定价或开团权下放给商家/自提点 |
| 供货商 | 开团前确认供货价、数量、送仓时间；按采购单送货 | 不登录系统、不直接面对消费者 |
| 平台仓库 | 收货、数量/品质/批次验收、按自提点分拣、出库 | 不自行定价或处理消费者支付 |
| 配送方 | 平台自配或第三方承运，从仓库配送到自提点 | 一期不要求物流系统 API 对接 |
| 合作自提点 | 收货、短时保管、确认到货、核销、记录现场问题 | 不推广、拉新、发团、定价或查看全局数据 |
| C 端用户 | 选择自提点、下单付款、到点取货、申请售后 | 不跨未开放地区下单 |

## 核心链路

```mermaid
flowchart LR
  A[平台确定货源与供货条件] --> B[商品上架并创建团期]
  B --> C[用户选自提点并在线支付]
  C --> D[截单：系统汇总已付款订单]
  D --> E[平台采购单]
  E --> F[供货商送货至平台仓库]
  F --> G[验收、分拣、生成配送批次]
  G --> H[配送至合作自提点]
  H --> I[点位确认到货，平台通知用户]
  I --> J[用户凭取货码领取]
```

## 团期与订单规则

- 团期不定期开启，依据农产品成熟、到货和可售批次决定。
- 一个团期内的商品共享一个截单时间和一个预计自提时间；购物车不得跨团期。
- 用户下单时在线支付；采购、分拣和配送只以已付款订单为准。
- 截单前允许用户自助取消并全额退款；截单后至到货前由运营审核；已取货的缺货、破损或品质问题可提交售后凭证。
- 货到点后，用户可在到货当天及次日取货；到期前提醒，逾期未取进入运营待处理。

## 商品与仓配范围

- 一期主卖常温可存放的农产品、干货和真空熟食。
- 商品必须具备规格、供货价、售价、可供数量、产地、批次、保质期/存放要求等信息。
- 需要冷链的鲜肉、乳制品和易腐鲜果蔬不作为一期重点，待具备对应仓储和配送条件后单独开放。
- 供货商结算以平台仓库验收合格的数量和批次为准。

## 全国扩展方式

- 系统的服务网络按“省 → 市 → 区县 → 自提点”建设。
- 只有已有平台仓库覆盖、配送线路和合格合作自提点的地区可下单。
- 未开放地区的用户可以提交所在省、市、区县的开通意向，作为开点与仓配扩张依据；一期不提供快递到家。

## 系统形态

- 一个运营后台：平台运营、仓库和履约人员按角色使用同一后台。
- 一个小程序：消费者购物；已获点位授权的核销员通过同一个小程序的受限“自提工作入口”执行核销；到货确认当前由履约人员完成，待建立可审计的点位映射后再下放。
- 一期不建设供货商后台、团长端、独立门店端或独立司机端。

## 结算原则

- 用户：下单预付；退款遵循团期和售后规则。
- 供货商：仓库验收合格后结算。
- 合作自提点：按已完成核销的订单支付固定服务费，不按销售额抽佣。

## 一期明确不做

- 好友凑人数成团、团长推广拉新、团长自营店、商家自助开团。
- 快递到家、冷链生鲜、第三方物流 API 深度对接。
- 供货商、司机、门店等独立系统。

## 待运营确定的数值参数

- 每期截单和预计自提日期。
- 自提点核销服务费与结算周期。
- 售后时限、供货商账期和验收争议处理。
- 起步仓库、首批区域与自提点覆盖计划。
