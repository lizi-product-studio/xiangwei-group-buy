## 对抗性发现

### QG-PL-01 — 行政目录包含被过度表述为“在服务区内”（P1）

- 事实状态：目录包含算法是 `CONFIRMED`（已冻结契约）；ServiceArea 是否恒等于无重叠行政边界是 `BLOCKING_UNKNOWN`；当前文字会导致范围过度声明是 `EVIDENCE_INFERRED`。
- 反证：`docs/09-api-data-contract.md` 只定义了 reverse `adcode` 与 `ServiceArea.regionCode` 的目录祖先/后代关系。它能证明行政路径相容，不能证明该坐标落在业务实际配送边界、正确门牌或可通行的自提地点。`docs/02-glossary.md` 将服务区定义为“运营配置的可服务范围”，但输入中没有确认每个 ServiceArea 恒等于一个不重叠的行政目录节点。
- 最早责任源：Requirements（DR-017/018、REQ-015 和 ServiceArea 义缩）；Architect 负责后续校验边界。
- 最小修订：确认并登记“本轮 ServiceArea 仅以一个行政目录节点表达、不承诺自定义几何边界”；所有错误、测试和发布文案统一称“行政区路径不一致”，不得宣称已验证实际服务几何边界。如果允许自定义、嵌套或重叠服务区，则当前契约不充分，必须回到 Requirements/Architecture，不得由 Engineering 自行补成地理围栏。
- 重进证据：ServiceArea 语义的明确事实状态；省/市/区及边界相邻夹具；明确的残留风险文案。

### QG-PL-02 — 生产反向编码提供方与目录映射契约缺失（P1）

- 事实状态：本地拟定的适配方向为 `EVIDENCE_INFERRED`；真实提供方、映射质量与供应链条件为 `BLOCKING_UNKNOWN`/`BLOCKING_EXTERNAL`。
- 反证：`docs/08-system-design.md` 同时写“高德 Key（可选）或 OSM 回退”，而 API 契约要求 canonical reverse `adcode`。输入中没有证据证明两个提供方都能返回可与本地目录稳定映射的代码，也没有确认生产提供方、调用条款、地址数据外发、归属/署名、限流、超时和缓存责任。OSM 不得被当作无条件的生产免费备援。
- 最早责任源：Architect（地理适配器、坐标系、错误契约）；用户/发布责任人批准真实提供方和 Key。
- 最小修订：允许 Engineering 先做提供方无关的适配器和确定性夹具；适配器输出必须含坐标系、原始行政标识、规范化目录节点和“不可映射”显式状态。未配置已批准生产适配器时 fail closed，不转入未批准的公共 OSM 端点，不伪装为空结果。
- 重进证据：契约/单元夹具可证明 GCJ-02/WGS84 边界、目录映射和不可映射安全失败；生产发布仍需经用户授权的真实提供方证据。

### QG-PL-03 — “历史位置待核验”与“不持久核验状态”存在可实现性缺口（P1）

- 事实状态：不持久核验字段和不在非位置编辑中调用逆编码是 `CONFIRMED`（冻结契约）；因而无法稳定声明持久已/未核验状态是 `EVIDENCE_INFERRED`。
- 反证：UX/DR-019 要求识别和展示“历史位置待核验”，但 API/数据契约明确不持久核验时间、提供方或标志，同时又要求纯非位置编辑不调用新的逆编码。在这些限制下，系统没有稳定事实可判定某条记录已核验/未核验，也不能支持持久的“已核验”展示声明。
- 最早责任源：Requirements 负责确定是否需要持久状态；Architect 负责最小数据/API 契约。
- 最小修订：本轮不新增迁移，因此删除任何持久“已核验”的暗示；将规则收紧为可无状态判定的事件触发：新建、地址/坐标变化、以及任何 inactive→active 都当场核验；位置未变的非状态编辑原样保留且不宣称当场核验。若产品必须区分“已/未核验”，则另建数据契约与迁移/回滚任务，不由实现者暗中推断。
- 重进证据：PATCH 触发矩阵（地址变、坐标变、启用状态变、纯非位置变）和 UI 文案的一致验收。

### QG-PL-04 — 农村/上游失败恢复尚不完整，现有回滚说法不安全（P1）

- 事实状态：现有 UX 覆盖的失败状态与 ADR 回滚文字是 `CONFIRMED`（文档事实）；真实农村可恢复性为 `BLOCKING_UNKNOWN`；回滚可导致放宽的判断为 `EVIDENCE_INFERRED`。
- 反证：UX 覆盖搜索无结果、搜索失败和逆编码失败，但未定义地图瓦片/地图交互本身不可用时的状态，“保留草稿”也未说明只是当前表单会话，不是持久草稿。ADR 又说可回滚到“现有位置编辑行为”，同时禁止以放宽跨区保存绕过；而已记录的现有行为正是不在服务端核验行政路径，两者不能同时成立。
- 最早责任源：UX 负责可见失败恢复；Architect 负责写入边界和回滚安全性。
- 最小修订：增加“地图不可用”状态，保留当前表单输入，允许重试/取消，但不得保存新建、位置变更或 inactive→active。回滚应保留 API 安全拒绝，或在整个定位写路径关闭时明确禁用这三类写入；不得回到“可保存未核验坐标”。文档应明说当前最小契约只保留本次打开表单内的输入/图钉；持久草稿不在范围。
- 重进证据：搜索、地图、逆编码分别失败的 UI/API 状态；失败时零位置写入；回滚/配置缺失时的 fail-closed 测试。

### QG-PL-05 — 50 米重复提示可保留，但不得被当作已验证业务规则（P2）

- 事实状态：`DEFAULT_ASSUMPTION`；输入中没有可将其提升为 `CONFIRMED` 的运营样本。
- 当前做对的部分：只在同一 `serviceAreaId` 内发出可覆写提示；不自动合并/删除；持续标注为 `DEFAULT_ASSUMPTION`。
- 实现前细化：PATCH 必须排除当前点位本身；地址规范化规则必须确定性且有中文标点/空格/全半角夹具；距离计算必须声明使用持久坐标系及球面公式；首次候选和明确覆写都记审计。不应新增稳默自动合并、持久 POI ID 或复杂地址治理。
- 反证条件：若真实试运营中高频出现合法独立点被提示，或真重复点大量超过 50 米，将样本和覆写记录回报 Requirements；未有数据前不创建任何新数字门槛。
