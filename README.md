# 乡味集团购平台

面向地方农产品和常温真空熟食的“平台统一采购、按团期集中送达”系统。

> 模式 B（平台统一采购、统一销售和统一履约）采用独立的销售、采购、仓储、履约和财务表；旧多商户撮合订单仅保留查询、退款与历史分账兼容。发布顺序、数据核对与回滚见 [模式 B 发布说明](docs/mode-b-rollout.md)。

## 当前履约模式

1. 平台选品、采购、定价，并按**收货区域**开团。
2. 用户下单后立即支付；截团后，运营统一备货。
3. 开团前，运营在目的地区域选择一个已启用的**本团固定集中领取点**；用户下单时确认该点。
4. 运营人工预约货拉拉，将整批货送至该固定领取点；到货时间与车辆信息会在履约过程中更新。
5. 到货确认后，订单开放取货码，用户集中领取。

收货区域是长期可开放的服务范围；集中领取点属于某一个团期，但在开售前必须由运营选定，并贯穿下单与核销。

## 已实现

- 小程序：选择收货区域和本团固定领取点、商品/团期浏览、购物车、立即支付、订单、到货取货码和“我的”。
- 运营平台：供货与商品、按区域开团、收货区域管理、地点确认、人工约车登记、发车、到货、订单、结算和操作留痕。
- 后端：团期配送计划、库存预占、订单幂等、模拟/微信支付适配边界、取货码核销和财务流水。
- 数据库：MySQL 迁移已新增 `campaign_delivery_plans`，把新订单关联到收货区域和团期配送计划。

## 本地运行

需要 Node.js 22+ 与 pnpm 11+。

```bash
pnpm install
pnpm dev:api
pnpm dev:admin
```

运营后台：`http://127.0.0.1:5173`

### 更新代码后的本地重启

如果本地接口是在本次更新前启动的，或页面仍出现旧的固定自提点逻辑，请先在启动接口的原终端按 `Ctrl+C`，再重新执行 `pnpm dev:api`。接口健康检查地址为 `http://127.0.0.1:3100/health/ready`；返回 `status: ok` 后再刷新后台或小程序。

小程序：在微信开发者工具中导入 `apps/miniprogram`。本地调试时，API 默认地址为 `http://127.0.0.1:3100`；微信开发者工具需按本地开发规则配置请求域名校验。

如需使用 MySQL 和 Redis：

```bash
# 第一次使用时先复制 .env.example 为 .env，并将 DATA_STORE、QUEUE_DRIVER
# 分别改为 mysql、redis（本地默认连接信息已经写在示例文件中）。
pnpm infra:up
pnpm db:migrate
pnpm dev:api
```

API 会自动读取项目根目录的 `.env`；本地 API 使用 MySQL 与 Redis 时，无需再在终端重复配置环境变量。

已存在数据库升级到本版本时，必须执行全部未完成迁移。它会补齐团期地点、商品快照、客服闭环、核销授权与通知事件的历史兼容数据；不要跳过任何编号。

小程序体验版和正式版不允许使用本机接口。上传前请通过受控发布配置注入对应 HTTPS API 域名和三条已审核的订阅消息模板 ID；服务端同时在 `.env.production` 配置相同的模板 ID 与字段映射。未填写有效配置时，小程序会明确阻止体验版/正式版启动，避免误发一个不可用的包。

## 上线前的外部输入

- 小程序主体、备案域名、微信认证与食品相关资质。
- 微信支付商户资料和真实小额支付验收。
- 微信订阅消息：地点确认、车辆发出、到货可领取通知。
- 货拉拉账号/合作方式；当前版本只登记人工约车信息，不接入货拉拉 API。
- 集中领取点变更、逾期未领取、退款和售后规则。

## 重要边界

- 一期仅支持常温预包装农产品和熟食；冷链、生鲜、散装和现制食品不在当前履约范围。
- 一个团期对应一个收货区域、一个开团前已选定的固定集中领取点。多区域商品可先复制开团；一团多区域是后续能力。
- 司机电话和货拉拉订单号仅在运营履约端可见，消费者只看地点、预计时间和订单状态。
